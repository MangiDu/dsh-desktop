# 05 · 风险与待验证项

## 0. 前置验证实验结果（2026-08-13 实测，V1–V5 + 补充 X1–X3 已完成）

实验方法：从本机 npx 安装直接 `node …/lib/bin.js web --port 0`，stdout 重定向到文件，curl/Node WebSocket 客户端模拟浏览器形态。全部实验环境已清理，无残留进程。

| # | 验证项 | 结果 |
|---|--------|------|
| V1 | 随机端口信任栅栏 | ✅ **通过**。loopback + OS 随机端口全链路放行：根页面 200 且 HTML 含 `__DSH_BOOT__` 注入；POST RPC（`settings.describe`、`session.list`）返回真实 `server-response`；伪造 `Host: evil.com` → 403；`Sec-Fetch-Site: cross-site` → 403；`Origin: http://evil.com` → 403；同源 Origin（WebView 形态）→ 200。**无需 `--trusted-host`**。响应不带 CORS 头（纯同源设计），WebView 只要加载与握手行完全一致的 URL 即天然同源 |
| V2 | 握手行格式 | ✅ **通过**。实际输出 `dsh web: http://127.0.0.1:<port>`，无 `(LAN: …)` 后缀（LAN 后缀仅绑 0.0.0.0 时出现，而 CLI 拒绝 0.0.0.0——解析器仍按"取第一个 URL、忽略后缀"实现以留容错） |
| V3 | 启动/安装耗时 | ✅ **数据到手**：dsh 进程 spawn→握手仅 **0.86–1.07s**（冷/暖安装无差别）；暖 npx 因本机 `~/.npm` 损坏**直接报错**（0.31s 失败，实证"不得依赖用户 npm 缓存"）；隔离缓存 npx 冷启动 **60.3s**；`npm install --prefix` 冷 bootstrap **60.2s / 334MB**。⇒ 首次安装必须给用户进度 UI（splash 60s+），后续启动秒级 |
| V4 | 无 TTY 兼容 | ✅ **通过**。stdout 管道重定向到文件，握手行正常打印、服务正常（dsh 不依赖 TTY） |
| V5 | SIGTERM 退出清理 | ✅ **通过**。SIGTERM 后主进程快速退出，`pgrep "bin.js web"` 无任何残留（无需强制杀进程组） |
| X1 | WebKit 风格请求头组合 | ✅ **通过**。Safari UA + `Sec-Fetch-Site: same-origin` + `Sec-Fetch-Mode: cors` + 同源 Origin → 200 server-response（WKWebView 形态与栅栏兼容） |
| X2 | 双实例并发 `--port 0` | ✅ **通过**。两实例同时启动分配到不同端口，互不干扰 |
| X3 | WebSocket 事件流 | ✅ **通过**。真实 WS 客户端连 `/api/events.mux` 升级成功、正常关闭（code 1000）；GET 无 Upgrade 头时返回 426 标准应答 |

**结论：方案核心假设全部验证通过。** 剩余 V6–V10 需在编码阶段执行（V6–V8 为 M3 更新系统演练，V9–V10 为多平台窗口行为验证）。

## 2. 主要风险与对策

| 风险 | 概率/影响 | 对策 |
|------|-----------|------|
| dsh rc 快速迭代，CLI/握手行/目录契约变化 | 中/高 | 壳只依赖两个已锁定的稳定契约（`--port 0` 与握手行前缀）；每次更新前跑冒烟验证（`--version` + `--dump-default-config`）；更新器支持锁定版本（"仅提示不自动更新"） |
| `latest`/`next` 通道语义变化（如 next 领先） | 中/中 | 通道可配（默认 latest）；设置页明示当前通道；检测逻辑仅比较 semver，不硬编码通道含义 |
| 系统无 Node/npm/pnpm | 高（分发场景）/高 | M2 起 bootstrap 明确检测并引导；M5 捆绑 Node sidecar 彻底解决；pnpm 缺失时禁用插件管理入口并提示 |
| 本机 `~/.npm` 缓存损坏类环境问题 | 已实证/中 | 全部 npm 操作强制 `--cache <appdata>/npm-cache`（硬约束） |
| 更新后新版本启动失败导致"白屏" | 低/高 | 自动回滚（指针回退 + 重启旧版）+ 错误页说明；历史版本保留 2 个 |
| 端口/多开冲突 | 低/低 | `--port 0` + 单实例插件，冲突基本不可能发生 |
| WebView 与 dsh 信任栅栏/CSP 兼容性 | 低（V1 已验证 HTTP 层通过）/高 | 已实测通过；残留引擎级差异并入 M1 验收；预案 `--trusted-host` 或壳内反向代理（last resort） |
| 重启丢会话 | 确定/中 | 产品文案明示 + 重启确认弹窗；未来可探索 dsh 会话恢复（`--resume`，观察 dsh 后续版本是否稳定） |
| Windows 引号/进程树清理差异 | 中/中 | spawn 用 `Command` + 显式参数数组（不经 shell）；kill 用 `taskkill /T`；CI 三平台矩阵 |
| npm 供应链 | 低/高 | 固定精确版本安装、校验 registry 返回的 shasum/integrity、可配镜像、安装目录权限收敛 |
| macOS 公证/签名复杂度 | 中/中 | 仅影响 M5；提前备好证书与 CI 密钥流程 |

## 3. 备选方案记录（ADR 摘要）

| 议题 | 选择 | 备选与弃因 |
|------|------|-----------|
| 前端承载 | WebView 直连 dsh 本地服务 | 打包静态前端不可行（`window.__DSH_BOOT__` 仅服务端注入，01§3） |
| dsh 安装方式 | 受管目录 `npm install --prefix` 版本化安装 | 全局 npm 安装：污染用户环境、多版本不可回滚；npx 每次冷启动：慢且不可控 |
| Node 来源 | 一期系统 Node，M5 捆绑 sidecar | 一期即捆绑：拖慢 M1–M3 迭代；永远依赖系统：分发脆弱（M5 是终点） |
| 更新通道 | 自研 dsh 更新器（registry + 蓝绿） | 复用 tauri-plugin-updater 更新 npm 包：机制不匹配（该插件面向壳二进制，dsh 是 JS 运行时，且需 semver 通道/镜像策略） |
| 进程形态 | dsh 作为受监督子进程 | Tauri sidecar（externalBin）：sidecar 面向打包二进制，dsh 是 Node 脚本，子进程 + 应用数据目录更灵活（M5 的 Node 捆绑才是 sidecar 的正确用法） |
| 更新生效 | 重启子进程 + 重载 WebView | 热切换：dsh 会话态在进程内，不可行（03§5） |

## 4. 依赖的 dsh 契约清单（若升级破坏需感知）

1. `dsh web` 与 `--port 0`（端口 0 = OS 分配）—— `@deepseek-ai/dsh-web-app/startup`。
2. 握手行 `dsh web: http://<host>:<port>`（stdout）—— `dsh-web-app/lib/index.js:107`。
3. `--version` / `--dump-default-config` 输出稳定 —— 更新器验证用。
4. 会话目录 `~/.dsh/sessions/<cwd>/` —— "打开文件夹"体验依赖。
5. 信任栅栏对 loopback + 随机端口的默认放行 —— **已实测验证（§0 V1/X1/X3）**。

以上契约在每次更新后由冒烟验证自动复核（M3 的 verify 步骤），破坏时更新器拒绝切换并报告。
