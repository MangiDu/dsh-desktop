# 02 · 总体架构

## 1. 进程与模块全景

```
┌─────────────────────────── dsh-desktop.app (Tauri 2) ───────────────────────────┐
│                                                                                 │
│  ┌─────────────── Rust 主进程 (src-tauri) ───────────────────────────────┐      │
│  │                                                                       │      │
│  │  runtime::RuntimeManager        — 版本指针、路径、settings.json        │      │
│  │  dsh::ChildSupervisor           — 子进程 spawn/监督/握手行解析/重启    │      │
│  │  updater::RegistryClient        — registry 版本检测 (reqwest)          │      │
│  │  updater::Installer             — 蓝绿安装 + 验证 + 原子切换           │      │
│  │  updater::Scheduler             — 自动检查计时 / 手动触发              │      │
│  │  commands::*                    — Tauri #[tauri::command] 面向壳 UI    │      │
│  └───────────────┬───────────────────────────────────────────────────────┘      │
│                  │ spawn + 监督                                                     │
│  ┌───────────────▼───────────────────────────────────────────────────────┐      │
│  │  dsh 子进程: node <runtime>/@deepseek-ai/dsh/lib/bin.js web --port 0  │      │
│  │   cwd = 用户项目目录   env = 继承 + DSH_HOME(默认) + 代理透传            │      │
│  │   stdout → supervisor (解析 "dsh web: http://127.0.0.1:<port>")        │      │
│  └───────────────────────────────────────────────────────────────────────┘      │
│                                                                                 │
│  WebView 主窗口 ──(加载)──► http://127.0.0.1:<port>   ← dsh Web 服务(注入 __DSH_BOOT__)
│  WebView 壳窗口 ──(加载)──► 壳自带 UI (splash / 错误页 / 设置页 / 更新进度)          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

要点：
- **两个 WebView 内容域分离**：主窗口加载 dsh 服务（`http://127.0.0.1:<port>`）；壳自己的页面（splash、错误、设置、更新进度）是壳仓库内置的静态资源（`tauri://localhost` 或本地文件），由 `commands::*` 提供数据。二者互不侵入。
- **单实例**：`plugin-single-instance`，二次启动聚焦已有窗口。
- **托盘**（可选 M4）：显示运行状态、检查更新、退出。

## 2. 目录布局

### 2.1 仓库（monorepo，pnpm workspace）

```
dsh-desktop/
├─ package.json / pnpm-workspace.yaml
├─ apps/desktop/
│  ├─ src-tauri/                  # Rust 主进程
│  │  ├─ Cargo.toml
│  │  ├─ tauri.conf.json
│  │  ├─ capabilities/default.json
│  │  └─ src/
│  │     ├─ main.rs / lib.rs
│  │     ├─ runtime/{mod,paths,settings}.rs
│  │     ├─ dsh/{supervisor,handshake}.rs
│  │     ├─ updater/{registry,installer,scheduler}.rs
│  │     └─ commands/{dsh,update,settings,fs}.rs
│  └─ ui/                         # 壳 UI（Vite + TS，无框架或轻量框架）
│     └─ src/{splash,error,settings,updates}/
└─ .intermediate/2026-08/13/001-tauri_wrapper/   # 规划文档
```

### 2.2 应用数据目录（运行时状态）

macOS `~/Library/Application Support/dsh-desktop/`，Windows `%APPDATA%\dsh-desktop\`，Linux `~/.config/dsh-desktop/`：

```
dsh-desktop/
├─ runtime/
│  ├─ current                       # 符号链接或指针文件 → versions/<active-version>/
│  └─ versions/
│     └─ 0.1.0-rc.6/
│        ├─ package.json            # npm install --prefix 的锚点
│        └─ node_modules/@deepseek-ai/dsh/{lib/bin.js, package.json, …}
├─ npm-cache/                       # npm --cache 独立缓存（规避 ~/.npm EPERM）
├─ logs/dsh-<ISO时间戳>.log         # 子进程 stdout/stderr 全量落盘
├─ settings.json                    # { channel, autoUpdate, intervalHours, lastCheck, registry }
└─ .locks/                          # 单实例/更新互斥锁
```

`current` 指针实现：优先文件指针（内容为版本目录路径）+ `rename` 原子替换（Windows 上对符号链接不友好，指针文件跨平台最稳）。

## 3. 运行时路径解析与启动序列

```
应用启动
  ├─ 1. 解析应用数据目录；读取 settings.json（首次运行写默认值）
  ├─ 2. runtime/current 指向的版本存在且 node_modules/@deepseek-ai/dsh 完整？
  │     ├─ 否 → 进入 bootstrap 流程（见 §5），splash 显示安装进度
  │     └─ 是 → 继续
  ├─ 3. 确定 dsh 子进程 cwd：
  │        优先级: 命令行参数/最近打开目录(settings.lastProjectDir) > 用户主目录
  │        （M4 提供"文件 → 打开文件夹"切换 cwd，切换 = 重启子进程 + 刷新 WebView）
  ├─ 4. spawn: node <current>/node_modules/@deepseek-ai/dsh/lib/bin.js web --port 0
  │        stdout/stderr 管道 → 落盘 logs/ 并逐行扫描握手行
  ├─ 5. 握手成功（超时 30s，见 §6）→ 主 WebView 加载 http://127.0.0.1:<port>
  │        期间用户看到 splash（壳 UI 窗口）
  └─ 6. 进入稳态：事件循环监听子进程退出 / 更新触发 / 退出信号
```

`env` 构造：继承父进程环境（PATH 必须含 node/npm/pnpm，一期依赖系统工具链）+ `DSH_HOME`（默认不覆盖，尊重用户已有会话库）+ 用户设置的代理变量透传。**不设置 `DSH_WEB_URL`**——dsh 会根据实际绑定地址自行计算（`localWebUrl`），壳只需保证 WebView 与握手行 URL 一致。

## 4. 关闭与监督（生命周期）

| 事件 | 壳行为 |
|------|--------|
| 用户退出应用 | 先 SIGTERM 子进程，等 3s，未退则 SIGKILL；随后自身退出 |
| 子进程异常退出 | 主 WebView 切到错误页（显示 logs 尾部 + "重启 dsh / 查看日志 / 更新后重试"按钮） |
| 子进程 stdout 卡死（无握手行） | 30s 超时 → 错误页（区分：Node 缺失 / 依赖损坏 / 端口无碍因 `--port 0` 基本不会发生） |
| WebView 加载失败 | 壳检测 `on_page_load` 失败后轮询重试（dsh 服务可能刚重启） |
| 更新完成 | SIGTERM 旧子进程 → 重解析 `current` → 重新走启动序列 §3.4–5 → WebView 重载 |
| macOS 全部窗口关闭 | 默认隐藏窗口、进程与托盘常驻（可配置为退出） |

崩溃自愈：主进程 `plugin-process` 或原生 watchdog 不做过度设计，M4 仅在连续 3 次启动失败时弹出"重置运行时"入口（删除损坏版本、回退指针）。

## 5. 首次安装（bootstrap）

无任何可用运行时（新用户/目录被清）时：

1. 检测系统工具链：`node -v`（≥ 22）、`npm -v`；缺失 → 引导页给出安装指引（或 M5 起使用捆绑 Node）。
2. 从 registry 取目标版本 tarball 元数据。
3. `npm install @deepseek-ai/dsh@<ver> --prefix versions/<ver> --cache npm-cache --no-audit --no-fund --loglevel error`（**必须带 `--cache`**，见 01§6）。
4. 验证：`node <dir>/node_modules/@deepseek-ai/dsh/lib/bin.js --version` 输出匹配。
5. 写 `current` 指针 → 继续启动序列。

## 6. 超时与重试参数（初始值，可调）

| 参数 | 初始值 |
|------|--------|
| 握手行等待超时 | 30 s |
| bootstrap 安装超时 | 10 min（实测本机冷安装 60s，慢网络余量放大） |
| WebView 加载重试 | 3 次 × 2 s 间隔 |
| SIGTERM→SIGKILL 宽限 | 3 s |
| 自动更新检查间隔 | 每 12 h + 启动时（可关） |

## 7. 壳 UI 的 Tauri 命令面（前后端接口草案）

```
dsh_status()          -> { state, version, url, port, pid, cwd }
dsh_restart(cwd?)     -> 重启子进程
dsh_open_log()        -> 返回最近日志路径（配合 opener 打开）
update_check()        -> { available, current, latest, channel, publishedAt }
update_apply()        -> 蓝绿安装 + 切换（进度经 event: update-progress）
update_rollback()     -> 回退上一版本并重启
update_settings_get/set() -> { channel, autoUpdate, intervalHours, registry }
app_open_project()    -> 文件夹选择 + 切换 cwd 并重启
runtime_bootstrap()   -> 触发首次安装
runtime_reset()       -> 重置运行时（危险操作，二次确认）
```

事件流（Rust → 壳 UI）：`dsh-state-changed`、`update-progress`、`update-available`。

## 8. 权限与安全

- `capabilities/default.json`：主窗口（dsh 域）**只给极少的 core 权限**（无 fs/shell 直通），壳 UI 窗口给壳命令权限；把"远程页面调用壳命令"的暴露面压到最低。
- 永不把 dsh 端口绑定到非 loopback（与 dsh 自身安全策略一致，见 01§2）。
- npm 安装仅接受 `@deepseek-ai/dsh@<精确 semver>` 参数，防止供应链歧义；更新器校验 tarball 的 `shasum`/`integrity` 字段。
