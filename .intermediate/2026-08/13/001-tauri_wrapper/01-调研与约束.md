# 01 · 调研与约束

> 调研对象：本机 npx 缓存中的 dsh 安装（`@deepseek-ai/dsh@0.1.0-rc.6`，即当前运行本会话的 dsh）以及 npm registry 元数据。所有结论均可在此安装的 `node_modules/@deepseek-ai/{dsh,dsh-web-app,dsh-app-boot,dsh-host-webserver}` 内复核。

## 1. dsh 是什么、怎么启动

- `@deepseek-ai/dsh` 是一个 **Node.js ESM CLI** 包（`bin.dsh = lib/bin.js`，`"type": "module"`）。
- 命令形态（commander 分层解析）：
  - `dsh web` ≡ `dsh --profile web`：启动浏览器 UI（桌面包装的目标入口）。
  - `dsh --profile headless "任务"` / `--profile tui`：其他 surface，与本方案无关。
  - `dsh plugin --profile <name> <pnpm 参数>`：把剩余参数转发给 **pnpm** 管理 profile 的插件依赖。
  - `dsh --version` / `--dump-config`：版本与配置诊断（更新器验证安装会用）。
- 启动方式：`node <安装路径>/node_modules/@deepseek-ai/dsh/lib/bin.js web [flags]`（npx/pnpm 只是外层搬运工，直接调 bin.js 最稳定）。

## 2. Web 服务的可编程接口（桌面壳的握手协议）

来自 `@deepseek-ai/dsh-web-app/lib/startup.js` 与 `cordis.patch.yml`：

| 项 | 事实 |
|----|------|
| 默认端口 | `3080`（`port: !!js ctx.webStartup.port ?? 3080`） |
| `--port 0` | 让 OS 分配空闲端口（**桌面壳必须使用，规避端口冲突**） |
| `--host` | 仅允许 `127.0.0.1`；`0.0.0.0` 被显式拒绝（防远程代码执行暴露，安全红线） |
| `--trusted-host` | 扩展 `/api` 浏览器信任栅栏的额外 authority |
| 就绪信号 | 服务绑定后 stdout 打印 `dsh web: http://127.0.0.1:<port>`（`dsh-web-app/lib/index.js:107`）——**稳定的就绪握手行，含真实端口** |

结论：桌面壳以 `--port 0` 启动 → 逐行扫描 stdout 解析 `dsh web: http://…:<port>` → 得到 WebView 目标 URL。

## 3. 前端为何必须由 dsh 服务端提供（最关键的硬约束）

- Web 前端（`@deepseek-ai/dsh-web-frontend` 的构建产物）由 `@deepseek-ai/dsh-host-frontend-static` 服务。
- 只有 `dsh web` 服务端会向页面注入 `window.__DSH_BOOT__`（浏览器 roster、客户端模块清单等）；`apps/web` 的 Vite 入口**不是独立应用**。
- 因此：**桌面壳不能把前端静态文件打包进 Tauri 资源再 `loadURL(tauri://localhost)`**，WebView 只能加载 `http://127.0.0.1:<port>`。这同时意味着：壳自身不需要维护/同步前端代码，dsh 更新后前端随包自动更新。

## 4. 更新源与版本现状

- registry：`https://registry.npmjs.org/@deepseek-ai%2Fdsh`
- `dist-tags`：`latest = 0.1.0-rc.6`，`next = 0.1.0-rc.6`（截至 2026-08-13，两者相同）
- 全部版本：`0.0.1-rc.1, 0.0.1-rc.2, 0.0.1-rc.5, 0.1.0-rc.2, 0.1.0-rc.3, 0.1.0-rc.6` —— 发布节奏为 rc 快速迭代。
- **包内无任何自更新/更新提示机制**（`dsh-web-app` 中对 "update" 的引用仅为系统提示词文本，与本意无关）。更新能力 100% 由桌面壳承担。
- 更新通道语义：由于是 rc 迭代期，`latest` 与 `next` 目前等价；桌面壳提供通道设置（`latest`/`next`），并支持配置 registry 镜像（如 `registry.npmmirror.com`，网络受限环境刚需）。

## 5. 安装与插件机制对运行时的要求

来自 `@deepseek-ai/dsh-app-boot/lib/index.js`：

- bundle 解析顺序：**dsh 自身安装目录的 node_modules 优先**，其次才是 profile 目录的 pnpm node_modules。⇒ 桌面壳把整个包（含依赖闭包，约 60 个 `@deepseek-ai/*` 包）装进应用数据目录即可自给自足。
- profile 插件（外挂插件）由 pnpm 管理：`dsh plugin --profile web add <pkg>` 会在 profile 目录建 pnpm workspace。⇒ 完整保留插件能力需要环境里有 **pnpm**。
- 会话存储：`~/.dsh/sessions/<cwd 转义>/`，会话按工作目录分区。⇒ 桌面端把 dsh 子进程的 cwd 设为用户选择的项目目录，即可获得"每项目独立会话历史"的桌面体验，这也是相对浏览器版的核心增值。

## 6. 本机环境实测（2026-08-13）

| 项 | 实测结果 |
|----|----------|
| Node | v24.16.0（nvm） |
| npm | 11.13.0 |
| pnpm | 11.17.0 |
| `npm view @deepseek-ai/dsh …` | **EPERM 失败**：`~/.npm` 缓存含 root 属主文件（历史 npm bug 残留） |
| 暖 `npx @deepseek-ai/dsh --version` | **直接报错**（0.31s 失败）：同一缓存问题波及 npx ⇒ 桌面壳绝不可依赖 npx |
| `npm install --prefix` 冷 bootstrap（独立缓存） | **60.2s / 334MB**（实测 2026-08-13）⇒ 首次安装必须有进度 UI |
| `dsh web` spawn→握手行 | **0.86–1.07s**（冷/暖安装无差别）⇒ 后续启动秒级 |
| dsh 运行 | 正常（本会话即 dsh web 提供） |

⇒ **硬约束**：桌面壳的一切 npm 操作（安装、版本查询）必须 `--cache <appdata>/npm-cache`（独立缓存），不得依赖 `~/.npm`；更稳妥的是更新器用 registry HTTP API（reqwest 直接 GET）做版本检测，npm 仅用于安装。

## 7. Tauri 侧事实

- 当前稳定大版本为 **Tauri 2.x**（2024-10 起 GA），配套官方插件 2.x：`plugin-shell`（sidecar 进程）、`plugin-updater`（壳自更新）、`plugin-dialog`（打开文件夹）、`plugin-single-instance`、`plugin-opener`、`plugin-process`（重启）。
- Tauri 2 的 `WebviewWindowBuilder.url()` 支持直接加载外部 `http://127.0.0.1:<port>`（macOS WKWebView / Windows WebView2 / Linux WebKitGTK 均支持 loopback http）。
- 标准分发形态（macOS `.app` / Windows MSI / Linux deb-AppImage）；macOS 分发需签名 + 公证。

## 8. 由调研推导的硬约束清单（方案必须满足）

1. WebView 加载 dsh 本地服务 URL，永不打包 dsh 前端。
2. dsh 以 `--port 0` 启动并解析 stdout 握手行（不抢 3080、不多进程冲突）。
3. 运行时需要 Node；插件能力需要 pnpm。一期依赖系统工具链，二期捆绑 Node/pnpm sidecar。
4. 所有 npm 操作使用独立缓存目录（本机 `~/.npm` 已坏）。
5. 版本检测走 registry HTTP API（不受 npm 缓存问题影响）；安装走 `npm install --prefix`。
6. dsh 子进程 cwd = 用户项目目录（会话分区体验）。
7. 更新后必须重启 dsh 子进程（Node 进程内存态，热换不可行）。
8. 只监听 loopback；不将端口暴露到局域网（与 dsh 自身安全策略一致）。
