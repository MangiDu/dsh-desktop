# 04 · 实施路线图

> 原则：每个里程碑都有可运行、可验收的产物；M1 完成即可交付 MVP；更新系统（M3）依赖 M2 的受管运行时，依赖顺序不可跳跃。

## 总览

| 里程碑 | 内容 | 估时 | 验收标准 |
|--------|------|------|----------|
| M0 | 仓库脚手架 + 决策落地 | ✅ 完成（2026-08-13） | `pnpm install && pnpm tauri dev` 出空窗口 |
| M1 | MVP：壳 + 启动 dsh + WebView | ✅ 完成（2026-08-14，通过验收） | 双击即用 dsh，退出无残留进程 |
| M2 | 受管运行时（安装/指针/设置/日志） | 2d | 全新机器环境自动 bootstrap 成功 |
| M3 | 更新系统（检测/蓝绿/回滚/自动手动） | 2–3d | 手工构造新旧版本完成更新与回滚演练 |
| M4 | 打磨（单实例/托盘/打开文件夹/崩溃恢复） | 1–2d | 完整桌面体验检查单通过 |
| M5 | 分发（捆绑 Node sidecar / 壳自更新 / 签名） | 2d+（可选） | 三平台安装包 + 壳更新通道可用 |

合计：核心 7.5–10.5 人日；含 M5 约 10–13 人日。

## M0 · 仓库脚手架（0.5d）

**任务**
1. `pnpm init` + `pnpm-workspace.yaml`，创建 `apps/desktop/`。
2. Tauri 2 初始化（`create-tauri-app` 模板，TypeScript + Vite，无 UI 框架或 Svelte/vanilla 均可，建议 vanilla-TS 减依赖）。
3. 接入官方插件（锁定 2.x）：`plugin-shell`、`plugin-single-instance`、`plugin-dialog`、`plugin-opener`、`plugin-process`（M5 再加 `plugin-updater`）。
4. `capabilities/default.json` 最小权限基线；README/CI（`tauri build` 冒烟）。

**验收**：`pnpm tauri dev` 弹出空壳窗口；`pnpm tauri build` 产出可启动的 .app。

## M1 · MVP：双击启动 dsh（2–3d）

**任务**
1. `dsh::ChildSupervisor`：
   - spawn `node <dsh>/lib/bin.js web --port 0`（此阶段 dsh 路径先用系统 `npx @deepseek-ai/dsh` 或环境变量注入的路径，M2 换受管目录）。
   - stdout/stderr 逐行落盘 `logs/` 并扫描握手行 `dsh web: http://127.0.0.1:<port>`。
2. 启动时序：应用启动 → 壳 splash 窗口 → spawn → 握手成功 → 主 WebView `loadURL` 真实 URL → 关闭 splash。
3. 退出清理：SIGTERM → 3s → SIGKILL；验证退出后无 `node …/bin.js` 残留进程。
4. 握手超时/子进程退出 → 错误页（显示日志尾部）。

**验证项**：V1–V5 前置实验已于 2026-08-13 全部通过（见 05 §0），M1 仅剩真实 WebView 引擎复测（并入 M1 验收标准）；V2 解析器仍按"取第一个 URL、忽略后缀"实现。

**验收**：本机双击应用 → 出现 dsh Web 界面 → 能正常对话；退出后 `ps` 无残留。

## M2 · 受管运行时（2d）

**任务**
1. `runtime::RuntimeManager`：`appdata` 目录布局、`current` 指针（`current.tmp` + rename）、版本完整性检查（`node_modules/@deepseek-ai/dsh/lib/bin.js` 存在且 `--version` 可执行）。
2. bootstrap：首次运行自动 `npm install --prefix versions/<ver> --cache <appdata>/npm-cache …`（硬约束：独立缓存，规避本机 `~/.npm` EPERM）；进度经 `update-progress` 事件展示在 splash。
3. `settings.json` 读写（channel/autoUpdate/intervalHours/lastCheck/registry/lastProjectDir），带默认值与容错（损坏文件回默认）。
4. 启动序列改为 §3 完整流程（02 文档）；M1 的 npx 路径被替换。
5. `dsh_status` / `dsh_restart` / `dsh_open_log` 命令打通。

**验收**：把 appdata 目录改名模拟新机器 → 启动自动 bootstrap → 正常进入 dsh；重启应用秒开（不再走 npx 下载）。

## M3 · 更新系统（2–3d）

**任务**
1. `updater::RegistryClient`：reqwest GET registry → 解析 dist-tags/time/dist 元数据；semver 比较；镜像与通道配置；lastCheck 防抖。
2. `updater::Installer`：蓝绿安装（`npm install --prefix versions/<new>`）+ 完整性验证（`--version` / `--dump-default-config`）+ 原子指针切换 + 历史保留（最近 2 个）+ 失败清理。
3. `updater::Scheduler`：启动检查 + 12h 定时（`tokio::time`）+ 手动触发入口（菜单/托盘/设置页按钮）。
4. 壳 UI：设置页（更新开关/通道/镜像/检查按钮）、更新进度条（`update-progress`）、"更新就绪，重启生效"提示、回滚入口。
5. 重启生效链路：停旧子进程 → 以新指针重走启动序列 → WebView 重载；重启前确认弹窗（"会中断当前会话"）。
6. 自动回滚：新版本握手失败 → 指针回退旧版 → 错误页提示。

**验收（演练脚本，对应 05 清单 V6–V8）**
- V6 手工在 versions 放一个"高版本假包"（如改版本号的当前包副本）→ 检测到更新 → 安装/切换/重启 → `dsh_status.version` 变化 → 回滚恢复。
- V7 断网/镜像不可达 → 更新失败提示，dsh 运行不受影响。
- V8 安装中途 kill → 半成品目录被清理，current 不变。

## M4 · 桌面体验打磨（1–2d）

**任务**
1. 单实例（二次启动聚焦窗口）；托盘图标 + 菜单（打开/检查更新/退出）；Dock 行为配置。
2. "文件 → 打开文件夹"：`plugin-dialog` 选目录 → 记录 `lastProjectDir` → 重启子进程（cwd 切换）→ WebView 重载。验收点：不同目录打开 dsh，会话历史独立（`~/.dsh/sessions/<cwd>/`）。
3. 崩溃恢复：连续 3 次启动失败 → "重置运行时"入口（删损坏版本/回退指针）；错误页增加"更新后重试"按钮。
4. 日志查看入口（`opener` 打开 logs 目录）；设置页持久化校验。

**验收**：完整检查单（启动/切换目录/更新/回滚/崩溃恢复/退出清理）全绿。

## M5 · 分发（可选，2d+）

**任务**
1. **捆绑 Node sidecar**（自包含分发，摆脱系统 Node 依赖）：
   - 下载 Node 官方发行版（如 `node-v24.x-darwin-arm64.tar.xz`）→ 解压为 Tauri `externalBin` sidecar 或 resource 目录；
   - spawn 改为 `<bundled>/bin/node`；npm 用同发行版自带 npm（`<bundled>/lib/node_modules/npm/bin/npm-cli.js`）；
   - pnpm 能力：检测系统 pnpm，缺失时提示（或经 corepack 引导）。也可随包捆绑 pnpm 单文件。
   - 三平台矩阵：macOS arm64/x64、Windows x64、Linux x64（先 mac + win）。
2. **壳自更新**：`tauri-plugin-updater` + GitHub Releases `latest.json`（签名）。
3. **签名与公证**：macOS `APPLE_CERTIFICATE` + notarytool；Windows 代码签名；CI（GitHub Actions `tauri-apps/tauri-action`）产出三平台产物。

**验收**：干净虚拟机（无 Node）安装 → 双击可用 → 壳自更新走通 → dsh 运行时更新走通。

## 实施记录（2026-08-14 更新）

- M0/M1 已完成。产物：`apps/desktop/`（`src-tauri/src/dsh.rs` 进程监督 + `lib.rs` 窗口/命令 + Vite 壳 UI）。
- M1 验收实录：spawn→握手 0.86s 级；GUI 服务 200 + `__DSH_BOOT__` 注入验证；SIGKILL 崩溃后孤儿（pid 45997）被下次启动回收（`reaping orphan`）；错误路径显示 `start-failed` 且应用存活；退出/清理 0 残留。
- 环境适配：本机无 cargo-tauri 插件（用 npm `@tauri-apps/cli`）；cargo 缓存与 pnpm store 重定向到仓库内规避沙箱与损坏的 `~/.npm`；运行桌面应用需超出 workspace 的文件权限（应用数据写 `~/Library`），分发环境无此问题。
